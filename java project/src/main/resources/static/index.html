Dashboard

Typical flow: 1) add students (Roll No, Name, Branch, Batch) or import a PDF/Excel list → 2) add exam rooms → 3) create batches/courses (defaults A–G, plus your own) → 4) upload exam data as PDF/Excel or create exams manually → 5) generate the seating chart and download it as a PDF (with student list). Press Enter in any form to jump to the next field.

        Announcements

        Posted to the dashboard of every student in the chosen audience (“All students” = everyone).

        Audience filters combine: a batch + semester + roll-number list only notifies students matching all selected filters. Each targeted student also gets a notification (bell, top right of their portal) and a browser push if enabled.

        Push Notifications

        Broadcast a message to every registered device — send it now, schedule it for later (survives restarts), or keep it as a draft. Targeted per-student messages stay in Announcements. Delivery is automatic: failed tries are retried with backoff and dead subscriptions are retired on their own.

        Push notification templates

        Default wording for every notification type — exam published, seat published, announcements and the rest. Edit a template and press Save to change what students see in their bell inbox and in the browser push (with its icon) from the next event on. Placeholders in {braces} are filled in per event; editing text never changes seats, exams or audiences. Reset restores the built-in wording.

        Administrator session

        Sign out when you finish managing students, rooms, exams, or seating allocations. Unsaved changes may be lost.

        Sessions should expire after 30 minutes of inactivity. Serve the app over HTTPS in production and keep credentials in environment variables (.env.example).
